# 우리주기 기능 정리

코드 기준으로 정리한 현재 동작이다. 날짜는 모두 서울 기준이다.

## 역할과 화면

| 역할 | 되는 방법 | 하단 메뉴 |
| --- | --- | --- |
| 기록자 | 가입하면 누구나 기록자 | 오늘 · 기록 · 연결 · 마이 |
| 파트너 | 기록자의 코드로 연결되면 전환. 연결을 끊으면 다시 기록자 | 오늘 · 달력 · 이야기 · 연결 · 마이 |
| 운영자 | `npm run admin:grant`로 지정 (역할과 별개) | 마이에 "운영자 신고 관리"가 추가됨 |

로그인하지 않으면 홈에서 소개 화면(랜딩)을 본다. 랜딩의 미리보기는 DB를 읽지 않고 예시 기록을 실제 홈과 같은 계산으로 그린다.

## 1. 계정

- **누가:** 모든 사용자
- **저장:** 이메일, 비밀번호 해시(scrypt), 카카오 회원번호, 이름, 건강 정보 동의 시각, 세션(토큰 해시, 30일)
- **화면:** `/signup`, `/login`, `/join`, 카카오 로그인 버튼, `/consent`, 마이, 설정
- **규칙과 예외**
  - 이메일 가입에는 건강 정보 저장 동의가 필수다. 비밀번호는 8~128자, 이름은 1~20자다.
  - 카카오로 처음 들어오면 기록자로 가입되고, 동의 화면을 거쳐야 앱을 쓸 수 있다.
  - 동의 기능이 생기기 전에 가입한 계정도 동의 화면을 한 번 거친다. 동의 전에는 다른 화면을 쓸 수 없다.
  - 없는 이메일로 로그인해도 같은 시간이 걸려서 가입 여부가 드러나지 않는다.
  - 요청 제한: 가입 시간당 IP 10회, 로그인 15분에 IP 30회·이메일 10회.
- **회원 탈퇴:** 설정에서 한다. 생리 기록, 평소 주기, 배려 요청, 연결, 알림 구독, 세션, 내가 건 차단이 지워지고 개인정보가 비워져 다시 로그인할 수 없다. 카카오 앱 연결도 끊는다. 이야기에 쓴 글과 댓글은 "탈퇴한 사용자"로 남고, 나를 차단한 다른 사람의 기록도 남는다.

## 2. 생리 기록

- **누가:** 기록자
- **저장:** 시작일, 종료일(없으면 진행 중), 예측 제외 여부와 사유
- **화면:** 홈의 "오늘 시작했어요"·"오늘 끝났어요", `/records`의 달력과 "직접 입력·전체 기록"
- **기록하는 방법**
  - 홈에서 오늘 시작하거나 끝낸다.
  - 기록 탭 달력에서 시작일을 누르고, 끝난 날을 누른 뒤 저장한다. 시작일만 저장하면 진행 중이 된다.
  - 달력에서 날짜를 눌러 수정·삭제하고, 진행 중 기록은 "이날 끝났어요"로 끝낸다.
  - 직접 입력에서 날짜를 적고, "예측에서 빼기"를 고를 수 있다(사유 필수).
- **규칙과 예외**
  - 미래 날짜는 저장할 수 없다. 종료일은 시작일 이후, 오늘 이전이어야 한다.
  - 다른 기록과 날짜가 겹치면 저장할 수 없다. 진행 중인 기록은 오늘까지 이어진 것으로 본다.
  - 종료일 없는 기록은 시작 후 10일까지만 진행 중으로 본다. 그 뒤로는 끝내기를 잊은 것으로 보고 시작일만 칠한다.

## 3. 달력 표시

- **누가:** 기록자(홈·기록 탭), 파트너(홈·달력 탭)
- **저장:** 없음. 기록에서 매번 계산한다.
- **화면**
  - 진한 칸: 실제 생리. 진행 중이면 시작일부터 오늘까지다. 달이 바뀌어도 이어진다.
  - 점선 칸: 예상. 진행 중인 생리의 남은 날(내일~예상 종료일)과 다음 생리(예상 시작일~예상 종료일)다.
  - 연보라 칸: 가임기(추정).
- **규칙과 예외**
  - 하루에 표시가 겹치면 실제 기록 > 예상 > 가임기 순으로 하나만 그린다.
  - 지나간 날의 예상과 가임기는 그리지 않는다.
  - "오늘 끝났어요"를 누르면 남은 날의 점선이 사라지고 다음 생리 예상만 남는다.
  - 진행 중인 생리의 예상 종료일이 이미 지났으면 오늘까지만 칠하고 점선은 없다.

## 4. 주기 예측

- **누가:** 기록자. 파트너는 공유가 켜져 있을 때 결과 날짜만 본다.
- **저장:** 평소 주기만 저장한다(21~45일, 비워 둘 수 있음). 예측과 정확도는 저장하지 않고 매번 계산한다.
- **화면**
  - 홈: 달, "다음 생리까지 N일", "11월 25일 ~ 29일 사이" 같은 범위
  - 기록 탭 "내 주기": 보통 주기, 최근 범위, 보통 기간, 다음 생리 예상, 예측 정확도, 계산에서 뺀 주기, 평소 주기 입력
  - 평소 주기는 기록 탭과 설정 어디서든 바꿀 수 있다.

### 주기 길이 계산

1. 제외 표시한 기록의 양옆 간격을 뺀다.
2. 최근 간격 6개를 고른다.
3. 18일 미만, 50일 초과, 또는 중앙값과 10일 넘게 차이 나는 간격을 뺀다. 뺀 간격은 "계산에서 뺀 주기"로 보여준다. 중앙값은 18~50일 안의 간격으로 구한다.
4. 남은 간격 수에 따라 계산한다.

| 쓸 수 있는 간격 | 주기 길이 |
| --- | --- |
| 0개 | 평소 주기, 없으면 28일 |
| 1개 | 평소 주기 1/2 + 실제 1/2, 평소 주기가 없으면 실제 간격 |
| 2개 | 평소 주기 1/3 + 실제 가중 평균 2/3, 평소 주기가 없으면 실제 가중 평균 |
| 3개 이상 | 실제 가중 평균만 |

가중 평균은 가장 최근 간격에 6, 그 앞에 5, … 가장 오래된 간격에 1을 곱해 계산한다.

### 그 밖의 값

- **다음 생리 시작일:** 마지막 시작일 + 주기 길이
- **예상 범위:** 시작일 ±(쓴 간격들의 표준편차를 올림한 값). 최소 ±2일이다.
- **생리 기간:** 최근 기록 6개 중 종료일이 있는 기록의 평균, 없으면 5일. 기록이 없을 때의 5일은 날짜 계산에만 쓰고 "보통 기간"에는 표시하지 않는다.
- **가임기:** 쓸 수 있는 간격이 3개 이상일 때만 표시한다. 배란일은 예상일 14일 전이고 가임기는 그 5일 전부터 1일 뒤까지다. 배란 추정일은 파트너에게 보내지 않는다.
- **예측 정확도:** 지난 기록마다 그 전 기록만으로 예측했다면 며칠 틀렸는지 계산해 최근 6번을 평균한다. 제외한 기록과 18~50일을 벗어난 간격은 세지 않는다. 지금의 평소 주기를 과거 계산에도 쓴다. 간격이 3개 이상일 때 "최근 예측은 평균 N일 차이"로 보여준다.
- **간격 3개 미만:** "기록이 쌓일수록 정확해져요"를 보여준다.

### 예외

- 간격의 최댓값과 최솟값이 10일 넘게 벌어지면 가임기를 숨긴다.
- 예상 범위가 지나도 새 기록이 없으면 "예정일이 N일 지났어요"로 기다리고 가임기를 숨긴다.
- 쓸 수 있는 간격이 없고 가정한 예상 범위까지 지났으면 예상을 표시하지 않는다. 오래된 기록 하나만 넣은 경우다.
- 마지막 기록이 예측 제외면 예상을 표시하지 않는다.
- 평균 기간이 31일을 넘으면 "기록 확인 필요"로 보류한다.
- 모든 예측은 참고용 추정이며, 피임·배란 확인·진단에 쓸 수 없다고 화면에 안내한다.

## 5. 홈

- **기록자 홈:** 달, 오늘 상태 문구, 연결 상태, 시작·종료 버튼, 오늘 필요한 배려, 달력, 오늘 내 몸 카드
- **파트너 홈:** 날짜, 달, 오늘 상태 문구, 오늘 요청, 가임기(공유 시), 지난 요청, 최근 기록, 기록자의 달력
- **달:** 시작일이 그믐, 예상 주기의 가운데가 보름이다. 예상일이 지나면 다음 기록까지 마지막 모양에 머문다. 예측이 없거나 파트너에게 예측이 공유되지 않으면 고정 초승달이다.
- **문구:** 생리 중이면 "생리 N일째", 아니면 가임기 예상과 다음 생리까지 남은 날이다. 기록자 홈에서 쓸 말이 없으면 "기록이 쌓이면 달이 차올라요"를 보여준다.
- **오늘 내 몸:** 생리 중, 난포기, 가임기, 황체기 중 하나의 흔한 변화와 팁을 보여준다. 가임기를 계산할 수 없으면 생리 중일 때만 표시하고, 나머지 시기는 단정하지 않는다.
- **연결 끊기:** 홈에는 없고 설정에만 있다.

## 6. 파트너 연결

- **누가:** 기록자가 코드를 만들고, 상대가 입력한다.
- **저장:** 초대(코드 해시, 만료 시각, 상태), 연결(기록자, 파트너, 공유 항목, 공유 시작일, 일시정지, 공유 확인 안내 여부)
- **화면:** `/connect`(코드 만들기, 코드·링크 보내기, 코드 입력), `/join?code=`(확인 화면)
- **규칙과 예외**
  - 코드는 8자리, 15분 유효, 한 번만 쓸 수 있다. 입력하면 승인 없이 바로 연결된다. 새 코드를 만들면 이전 코드는 무효가 된다.
  - 자기 코드는 쓸 수 없다. 한 사람은 활성 연결을 하나만 가진다.
  - 이미 로그인한 사람은 링크를 열어도 "연결하기"를 눌러야 연결된다.
  - 코드 입력 요청 제한: 15분에 계정 10회, IP 30회. 코드 생성 제한: 시간당 10회.
  - 연결되면 상대는 파트너가 되고, 기록자에게 "파트너가 연결됐어요" 알림이 간다.
  - 파트너가 된 사람의 기존 기록은 지워지지 않고, 연결을 끊고 기록자로 돌아오면 다시 보인다.
  - 연결 끊기는 양쪽 모두 설정에서 할 수 있다. 다시 연결하면 공유 설정은 기본값으로 돌아간다.

## 7. 공유

- **누가:** 기록자가 정하고, 파트너가 본다.
- **저장:** 항목별 켜짐, 공유 시작일, 일시정지
- **기본값:** 새로 연결되면 생리 기록·다음 생리 예상·배려 요청은 켜지고 가임기는 꺼진다.
- **화면**
  - `/connect`의 토글은 누르는 즉시 저장된다.
  - 연결 후 기록자 홈에 "OO님에게 보이는 항목 확인하기"가 나온다. 누르면 연결 화면으로 가고 다시 나오지 않는다. 누르기 전까지는 계속 보인다.
- **파트너가 보는 조건:** 활성 연결 + 일시정지 아님 + 항목 켜짐 + 공유 시작일 이후

| 항목 | 파트너에게 보이는 것 |
| --- | --- |
| 생리 기록 | "생리 N일째", 최근 6개 기록, 달력의 실제 날짜 |
| 다음 생리 예상 | 달, 다음 생리까지 남은 날, 예상 범위, 달력의 예상 날짜 |
| 가임기 (추정) | 가임기 날짜와 달력 표시 |
| 배려 요청 | 최근 7일 중 "파트너에게 보내기"를 켠 요청 |

- **규칙과 예외**
  - 공유 시작일 기본값은 연결한 날이다. 생리 중에 연결하면 이번 생리의 시작일로 잡는다.
  - 공유 시작일 이전에 시작한 기록은 통째로 숨긴다. 공유 시작일은 기록자가 바꿀 수 있다.
  - 진행 중인 생리의 남은 날 점선은 생리 기록과 다음 생리 예상이 모두 켜져 있고 그 기록이 보일 때만 나온다.
  - 예측은 숨겨진 과거 기록까지 써서 계산하되 결과 날짜만 보낸다. 간격, 제외 사유, 평소 주기, 기록 id는 보내지 않는다.
  - 일시정지하면 파트너에게 "잠시 쉬는 중"만 보인다.

## 8. 오늘 필요한 배려

- **누가:** 기록자가 남기고, 파트너가 답한다.
- **저장:** 날짜별 요청 하나(고른 항목, 300자 한마디, 공유 여부), 답장(봤어요·도와줄게요·했어요)
- **화면:** 기록자 홈의 접힌 카드, 파트너 홈의 요청 카드
- **규칙과 예외**
  - 항목을 고르거나 한마디를 적어야 저장된다.
  - 보내려면 연결돼 있고, 배려 요청 공유가 켜져 있고, 일시정지가 아니어야 한다. 그렇지 않으면 나만 보이는 기록으로 남는다.
  - 내용이 바뀌면 예전 답장을 지운다.
  - 파트너는 답할 때도 서버에서 공유 조건을 다시 확인받는다. 답장은 바꿀 수 있다.
  - 처음 공유될 때만 파트너에게, 첫 답장 때만 기록자에게 알림이 간다.

## 9. 이야기 (파트너 커뮤니티)

- **누가:** 활성 연결이 있는 모든 파트너. 커플이 달라도 서로의 글을 본다. 기록자는 접근할 수 없다.
- **저장:** 글(제목, 본문), 댓글(본문, 답글이면 원 댓글), 신고, 차단, 이야기 닉네임
- **화면**
  - `/community`: 제목, 닉네임, 시간, 댓글 수. 최신순, 20개씩 더보기. 아래에 내가 쓴 글 목록.
  - `/community/[id]`: 제목, 본문, 댓글, 답글. 답글은 댓글 아래 들여쓰기로 보인다.
  - `/community/new`: 제목과 본문.
- **규칙과 예외**
  - 처음 쓸 때 이용 규칙에 동의하고 닉네임을 정한다(2~12자, 중복 불가, 비우면 무작위). 동의 전에도 읽기는 된다.
  - 제목 60자, 본문 2,000자, 댓글 500자까지다. 글과 댓글 각각 10분에 5개까지 쓸 수 있다.
  - 답글은 댓글에 한 단계만 달 수 있다. 답글에 답글을 달 수 없다.
  - 내 글과 댓글은 고치고 지울 수 있다. 글을 지우면 댓글이, 댓글을 지우면 답글이 함께 지워진다. 다른 사람이 쓴 답글도 포함된다.
  - 예전 질문·팁 글은 한 목록에 합쳐 보인다. 저장된 분류 값은 남아 있지만 화면에서는 쓰지 않는다.
  - 화면에 내려가는 값에는 작성자 id, 이메일, 앱 이름을 넣지 않는다.
  - 연결을 끊으면 이야기를 볼 수 없지만, 내가 쓴 글은 목록에서 지울 수 있다.
- **신고:** 내 글이 아닌 글·댓글을 한 번씩 신고할 수 있다. 처리 전 신고가 3건 쌓이면 자동으로 숨긴다.
- **차단:** 양방향이다. 서로의 글과 댓글이 보이지 않고 댓글 수에서도 빠진다. 차단한 사람의 댓글에 달린 답글도 함께 안 보인다. 차단을 푸는 화면은 없다.
- **운영자:** `/admin/reports`에서 신고를 숨김 또는 기각으로 처리한다. 기각하면 자동 숨김이 풀리고 그 신고는 다시 세지 않는다. 운영자는 숨긴 글도 읽지만 숨긴 글에 쓰기 동작은 할 수 없다.

## 10. 알림

- **누가:** 알림을 켠 사용자
- **저장:** 푸시 구독, 예정일 알림 켜짐, 마지막으로 알린 예정일, 새 소식 확인 시각
- **화면:** 마이의 알림 설정, 홈의 "새 소식" 표시
- **규칙과 예외**
  - 권한 요청은 버튼을 눌렀을 때만 한다. iPhone은 홈 화면에 추가해야 쓸 수 있다.
  - 예정일 3일 전이면 기록자 본인에게 "오늘 확인할 소식이 있어요"를 보낸다. 건강 정보는 문구에 넣지 않는다. 매일 오전 9시에 Vercel Cron이 돌고, 같은 예정일로는 한 번만 보낸다.
  - 파트너 연결, 배려 요청, 답장 때도 알림이 간다.
  - 알림을 거부한 사람도 홈의 "새 소식"으로 확인할 수 있다.
  - 공식 푸시 서비스 주소만 받는다. 없어진 구독은 지운다. 알림이 실패해도 저장된 내용에는 영향이 없다.

## 11. 앱 동작

- **PWA:** 설치할 수 있다. 서비스 워커가 정적 파일과 마지막 페이지를 캐시하고, 페이지는 네트워크를 먼저 쓴다. 건강 정보가 든 페이지 캐시는 로그아웃·탈퇴 때 지운다.
- **상태 확인:** `/api/health`는 DB를 깨우지 않고 살아 있는지만 답한다.
- **로컬 개발:** `DATABASE_URL`이 없으면 내장 Postgres(PGlite)를 `.pglite`에 쓴다.
